# 复审提示词模板（双引擎判卷）

> 用法：第一引擎（如 deepseek-4.1-flash）审计完成后，第二引擎（建议更强模型，如 glm-5.3）开新会话粘贴本模板。
> 只需填三处：`<项目路径>`、终版结论三要素（从最后一轮轮末汇报抄）、可选的项目特殊看点。

## 模板

```
/audit 复审模式：第一遍完整答卷在 <项目路径>\audit-state\
（<引擎/模型名> 所出，<N> 轮至静态收敛，终版结论：独立通杀
<X> 条——<F 编号列表与类型>；链路资产 <C 条数>；<特殊裁决点，
如有：降级/组合链/许可环等>。判定口径为通杀六问）。

你的任务不是重跑，是判卷。只读结论层：state.json、chains.md、
findings/、log.md 收口段<如有 forensics.md / judgment.md 等特殊
产物则加>——不读 candidates/ 与全量中间产物，防锚定。

四类判卷对象（按优先级）：
1. 共同根基复核：多条 finding 共享的技术前提（鉴权链定论 /
   会话机制 / 净化器语义）独立重验——前提翻则成片塌方；
2. 最新判定验证：刚立档 / 刚降级的 finding 独立复核；
3. 近失链抽验：chains.md 中标"缺第 N 问"的链抽 5-8 条六问
   重判（重点攻⑤⑥语义裁定与"缺一环"是否真的卡死）；
4. 覆盖面：excluded 格子理由、recon 入口普查有无漏网、
   饱和度信号是否报早。
产出 = 误判纠正清单（file:line+原判定+新判定+依据）+ 维持/
推翻裁决书。轮末维护后汇报停等；报告门禁照旧——需更新报告
等我指令。
```

## 三次实战战绩（预期校准）

| 项目 | 目标 | 第一引擎产出 | 复审结果 |
|---|---|---|---|
| 中宝连锁V6 | .NET WinForms 反编译 | 9 轮零通杀 | **翻案 +1**：CH-05 组合链升格 F-001（deser RCE，⑥⑦语义翻正） |
| SALIA 充电桩 | PHP+MQTT 固件 | 8 轮 4 通杀 | **翻案 +1**：C-04 升格 F-007（upload-rce，答卷自己的规则自己没执行）；推翻"UPX ELF 静态阻塞"（Python lzma 全解包）；维持 F-001/F-002 植入物降级 |
| NUUO NVR | PHP+原生 CGI 固件 | 5 轮 1 通杀（F-003） | F-003 维持；纠正 5 处（探针判据失效 / sink 归属写反 / 兜底原语分层 / 基线计数 / A17 收窄补强） |

**复审的价值不在每次都翻案——零翻案时你拿到的是"敢拿去提交"的底气。**

## 判卷方的操作纪律

1. 只读结论层，源码按需抽验（判卷方亲读代码是必要的——历史上最高价值的翻案全部来自判卷方亲读）；
2. 纠正清单每条必须有 file:line 证据链，防"凭感觉翻案"；
3. 翻案后**不要直接改终版报告**——产出裁决书，等用户显式指令再改账。
