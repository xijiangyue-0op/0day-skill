# 白盒审计分类任务：任意文件读取 / 下载

本会话只审任意文件读取/下载（含路径穿越与文件包含），其他类别不展开（发现线索写入 `audit-findings/handoff.md` 一行带过）。

## 起点

优先读取 `audit-map.md` 中的文件读取 sink 清单；若不存在，先定位：FileInputStream / Files.read / FileReader / IOUtils.toByteArray / `response` 写文件流的接口，以及功能面线索：下载接口、导出、附件预览、模板加载、头像/静态资源按参数取文件。

## 审计要点

1. **source 可控性**：文件路径参数是否来自请求（filename / path / id 换文件名映射表是否可被 `../` 影响）
2. **穿越验证**：是否对 `..`、URL 编码（%2e%2e%2f、..%2f、双重编码）、分号、空格做了规范化；`getCanonicalPath` 后是否重新校验前缀（只 getCanonical 不校验等于没做）
3. **web 可读范围**：能否读出 webroot 之外（WEB-INF/web.xml、classes、配置数据库口令），这是评级关键
4. **利用链推导**（有价值的读取目标）：数据库配置文件 → 口令 → 进一步利用；WEB-INF/classes 反编译源码；秘钥/密文文件
5. **文件包含**（JSP include / PHP include require）：动态 include 场景评估（远程包含/本地包含到 webshell 日志）
6. **鉴权检查**：下载/预览接口常被 Filter 遗漏，逐个确认未授权可达性

## 排除项

只能读固定白名单文件的、路径完全服务端硬编码不可控的、需登录且确认无未授权路径的、纯目录列表无敏感内容的。

## 输出要求

结论写入 `audit-findings/fileread.md`，每个发现按此格式：

```
### [已确认|高度可疑|需动态验证] <一句话标题>
- 前端触发点：<完整 URL> + <参数名> + <请求方法>
- 调用链：source 文件:行号 → 路径拼接/规范化 文件:行号 → 读取输出 文件:行号
- 利用方式：穿越 payload 示例（含编码变形）+ 有价值的读取目标清单（如 ../../WEB-INF/web.xml）
- 危害评级：高危（可读任意文件/含口令的配置）/中危（限定目录内穿越）/低危
- 证据：关键代码原文
```

- 文件末尾附"已排查面"清单，明确结论："发现 N 个 / 未发现可确认漏洞"
- 上下文接近 80% 时把未完成部分写入"未完成"一节，提示开新会话继续

最后一轮对话给出简短总结：每个发现一句话 + 排查面概述。

## 通杀判定（新：每条发现必答）

对每条「已确认」发现额外回答五问，答案写进发现条目的「通杀」字段：
1. 未授权？（触发全程不需要任何账号口令；内部人滥用不算）
2. 默认部署成立？（无需管理员特殊配置；默认注释/禁用的能力须能被攻击者可写的配置激活才算）
3. 不依赖可轮换秘密？（管理员改一个口令/密钥就失效的入口不算；但以 SQL 注入等代码缺陷为入口的链不在此列）
4. 不依赖网络位置/本地前提？（无需同网段投毒、无需先落地本地文件写；公网明文端点是厂商部署事实，不受此限）
5. 不依赖员工账号？

判定：五问全过 = **通杀**（独立计数）。缺任何一问 = 在文件末尾「链路资产」节登记：链路 + 缺哪问 + 可与哪条通杀根组合（组合链不计数，仅作根的危害放大证据）。

## 状态落盘（新：接 audit-state 协议）

- 本类结论照旧写 audit-findings/<类别>.md；另在 audit-state/log.md 追加一行完成记录（含发现数）
- 若 audit-state/state.json 存在：把本类对应 coverage 格标 done/traced，新线索写入 next_round
- 涉及的发现编号 F-XXX（若主控已分配）保持一致；未分配编号时用位置 hash 临时标识
