# 白盒审计分类任务：SSRF

本会话只审 SSRF，其他类别不展开（发现线索写入 `audit-findings/handoff.md` 一行带过）。

## 起点

优先读取 `audit-map.md` 中的出站 HTTP sink 清单；若不存在，先定位所有发起出站 HTTP 请求的位置：URL / HttpURLConnection / HttpClient / RestTemplate / okhttp / 第三方 SDK 内部请求，以及功能面线索：远程图片取回、URL 预览/生成快照、webhook/回调配置、在线编辑器远程导入、代理/转发接口、聚合第三方登录、远程文件导入。

## 审计要点

1. **source 可控性**：目标 URL（全部或部分：host/path/query）是否来自请求参数、数据库（用户可写配置也算二次 SSRF）
2. **校验绕过**：是否根本没校验；校验了 host 白名单但 URL 解析可绕过（`@` 分隔 userinfo、`#`、重定向跟随、DNS rebinding 说明前提）；只校验 http/https 但允许 file:/ftp:/dict:/gopher:（Java 原生 URL 类各协议 handler）
3. **利用面评估**（决定评级）：
   - 内网可达性：能否打 `127.0.0.1`、`192.168.x` 段、已知内网服务端口
   - 回显：响应是否回传给用户（有回显 SSRF 探测价值高）；无回显时注明需盲打/延时
   - 协议：gopher/dict 可交互协议才可打 redis/fastcgi 之类，file:/ 可读本地文件
4. **二次 SSRF**：从数据库/配置读取的 URL 字段，回溯其写入入口是否用户可控
5. **鉴权检查**：每个 SSRF 入口确认未授权可达性

## 排除项

仅回显自身服务内网资产且无进一步利用的、需登录且确认无未授权路径的、只影响自身域名的（同域请求）。

## 输出要求

结论写入 `audit-findings/ssrf.md`，每个发现按此格式：

```
### [已确认|高度可疑|需动态验证] <一句话标题>
- 前端触发点：<完整 URL> + <可控参数> + <请求方法>
- 调用链：source 文件:行号 → URL 构造 → HTTP 发起 文件:行号
- 利用方式：内网探测 payload 示例、协议支持清单、回显与否
- 危害评级：高危（可打内网重要服务/gopher 可交互/云元数据）/中危/低危
- 证据：关键代码原文
```

- 文件末尾附"已排查面"清单，明确结论："发现 N 个 / 未发现可确认漏洞"
- 上下文接近 80% 时把未完成部分写入"未完成"一节，提示开新会话继续

最后一轮对话给出简短总结：每个发现一句话 + 排查面概述。

## 通杀判定（新：每条发现必答）

对每条「已确认」发现额外回答五问，答案写进发现条目的「通杀」字段：
1. 未授权？（触发全程不需要任何账号口令；内部人滥用不算）
2. 默认部署成立？（无需管理员特殊配置；默认注释/禁用的能力须能被攻击者可写的配置激活才算）
3. 不依赖可轮换秘密？（管理员改一个口令/密钥就失效的入口不算；但以 SQL 注入等代码缺陷为入口的链不在此列）
4. 不依赖网络位置/本地前提？（无需同网段投毒、无需先落地本地文件写；公网明文端点是厂商部署事实，不受此限）
5. 不依赖员工账号？

判定：五问全过 = **通杀**（独立计数）。缺任何一问 = 在文件末尾「链路资产」节登记：链路 + 缺哪问 + 可与哪条通杀根组合（组合链不计数，仅作根的危害放大证据）。

## 状态落盘（新：接 audit-state 协议）

- 本类结论照旧写 audit-findings/<类别>.md；另在 audit-state/log.md 追加一行完成记录（含发现数）
- 若 audit-state/state.json 存在：把本类对应 coverage 格标 done/traced，新线索写入 next_round
- 涉及的发现编号 F-XXX（若主控已分配）保持一致；未分配编号时用位置 hash 临时标识
