# 白盒审计分类任务：SQL 注入

本会话只审 SQL 注入，其他类别不展开（发现线索写入 `audit-findings/handoff.md` 一行带过）。

## 起点

优先读取 `audit-map.md` 中的入口点清单和 SQL sink 清单；若不存在，先快速自行清点（web.xml/注解路由 + Statement/MyBatis/Hibernate 执行点）再开始。

## 审计重点

1. **source→sink 完整链**：getParameter / getHeader / getCookie / @RequestBody / 路径变量 → 拼接 SQL。必须验证链路真实存在，只报有完整证据的。
2. **预编译救不了的位置**（重点排查）：
   - MyBatis `${}`（尤其 order by、in、like、表名/列名动态拼接）
   - String 拼接进 Statement.execute / prepareStatement 的 sql 变量
   - 动态排序字段（前端传 sort/order 参数直达 SQL）
3. **堆叠注入条件**：检查 JDBC 连接串是否 allowMultiQueries=true；确认后利用方式按堆叠写
4. **二次注入**：入库时转义/预编译，但回读后二次拼接的位置
5. **鉴权检查**：对每个 SQL 注入入口确认是否存在未授权路径（Filter/Interceptor 的 url-pattern 覆盖缺口、路径规范化绕过如 `/api/../api`）。确认无法未授权到达的才跳过，并在报告中说明"已确认需登录且无绕过"。
6. **易漏 sink 位（实测漏报源）**：catch/全局异常兜底里的日志 SQL 拼接（Request 值零转义进 Sys_error 类 INSERT）；会话身份值（login.LoginCode/Session 值）入 CommandText 的全文件族清点——凡 `X.xxx` 属性直拼 SQL 的都算一族。

## 排除项

XSS/CSRF/CRLF、弱口令/硬编码、纯报错信息泄露、需登录且确认无未授权路径的注入点。

## 输出要求

结论写入 `audit-findings/sqli.md`，每个发现按此格式：

```
### [已确认|高度可疑|需动态验证] <一句话标题>
- 前端触发点：<完整 URL> + <参数名> + <请求方法>（从路由配置推导）
- 调用链：source 文件:行号 → ... → sink 文件:行号（引用每步关键代码）
- 利用方式：可直接操作的 payload 与步骤
- 危害评级：高危/中危/低危 + 一句理由
- 证据：关键代码原文
```

- 文件末尾附"已排查面"清单（检查了哪些入口/哪些模式未命中），并明确结论："发现 N 个 / 未发现可确认漏洞"
- 置信度从严：只有链路完整、利用方式成立才是"已确认"；缺一环就是"高度可疑"
- 上下文接近 80% 时把未完成部分写入文件"未完成"一节，提示用户开新会话继续

最后一轮对话给出简短总结：每个发现一句话 + 排查面概述。

## 通杀判定（新：每条发现必答）

对每条「已确认」发现额外回答五问，答案写进发现条目的「通杀」字段：
1. 未授权？（触发全程不需要任何账号口令；内部人滥用不算）
2. 默认部署成立？（无需管理员特殊配置；默认注释/禁用的能力须能被攻击者可写的配置激活才算）
3. 不依赖可轮换秘密？（管理员改一个口令/密钥就失效的入口不算；但以 SQL 注入等代码缺陷为入口的链不在此列）
4. 不依赖网络位置/本地前提？（无需同网段投毒、无需先落地本地文件写；公网明文端点是厂商部署事实，不受此限）
5. 不依赖员工账号？

判定：五问全过 = **通杀**（独立计数）。缺任何一问 = 在文件末尾「链路资产」节登记：链路 + 缺哪问 + 可与哪条通杀根组合（组合链不计数，仅作根的危害放大证据）。

## 状态落盘（新：接 audit-state 协议）

- 本类结论照旧写 audit-findings/<类别>.md；另在 audit-state/log.md 追加一行完成记录（含发现数）
- 若 audit-state/state.json 存在：把本类对应 coverage 格标 done/traced，新线索写入 next_round
- 涉及的发现编号 F-XXX（若主控已分配）保持一致；未分配编号时用位置 hash 临时标识
