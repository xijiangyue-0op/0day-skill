# 白盒审计分类任务：文件上传（目标：RCE）

本会话只审文件上传，其他类别不展开（发现线索写入 `audit-findings/handoff.md` 一行带过）。

## 起点

优先读取 `audit-map.md` 中的入口点清单和文件写入 sink 清单；若不存在，先定位全部上传接口（MultipartFile、commons-fileupload、自研 multipart 解析、富文本/在线编辑器自带上传、头像/附件/导入等功能点）。

## 审计重点（逐层检查每个上传点）

1. **扩展名校验逻辑**：
   - 白名单还是黑名单？黑名单必查绕过：双写（`.jsp.png.jsp` 视情况）、大小写、`%00` 截断、分号（`a.jsp;png`）、空格、`::$DATA`
   - 白名单必查：是否用 `endsWith`/`indexOf` 判定（可被 `x.png.jsp` 类绕过）、是否取的最后一个点、是否校验的是 Content-Type 而非文件名
2. **文件头/魔数校验**：是否只校验后缀不校验内容；图片马 + 解析漏洞链
3. **存储路径**：是否保留原始文件名；存储目录是否 web 可达（能否直接 URL 访问上传物）；路径拼接是否可 `../` 穿越
4. **解压场景**（zip 导入/附件解压）：zip slip（`../` 写出解压目录）、解压后缀是否再校验
5. **Web 容器/中间件**：结合部署环境判断解析漏洞（IIS/Nginx/Apache/Tomcat 已知解析规则）
6. **不可直接 RCE 时的降级链**：任意文件覆盖→覆盖配置文件/定时任务/certutil 脚本→间接 RCE；上传 HTML→存储 XSS（仅记录，不展开）
7. **鉴权检查**：每个上传入口确认未授权可达性（导入/编辑器接口常被 Filter 遗漏）

## 排除项

XSS/CSRF、弱口令、需登录且确认无未授权路径的上传点。

## 输出要求

结论写入 `audit-findings/upload.md`，每个发现按此格式：

```
### [已确认|高度可疑|需动态验证] <一句话标题>
- 前端触发点：<完整 URL> + <参数名> + <请求方法>
- 调用链：入口 文件:行号 → 校验逻辑 文件:行号（原文）→ 存储落地 文件:行号
- 利用方式：具体可操作的上传步骤（构造的文件名/Content-Type/请求体要点）+ 访问路径推导
- 危害评级：高危（web 可达且能解析执行）/中危（覆盖/穿越降级链）/低危
- 证据：关键代码原文
```

- 文件末尾附"已排查面"清单，明确结论："发现 N 个 / 未发现可确认漏洞"
- 上下文接近 80% 时把未完成部分写入"未完成"一节，提示开新会话继续

最后一轮对话给出简短总结：每个发现一句话 + 排查面概述。

## 通杀判定（新：每条发现必答）

对每条「已确认」发现额外回答五问，答案写进发现条目的「通杀」字段：
1. 未授权？（触发全程不需要任何账号口令；内部人滥用不算）
2. 默认部署成立？（无需管理员特殊配置；默认注释/禁用的能力须能被攻击者可写的配置激活才算）
3. 不依赖可轮换秘密？（管理员改一个口令/密钥就失效的入口不算；但以 SQL 注入等代码缺陷为入口的链不在此列）
4. 不依赖网络位置/本地前提？（无需同网段投毒、无需先落地本地文件写；公网明文端点是厂商部署事实，不受此限）
5. 不依赖员工账号？

判定：五问全过 = **通杀**（独立计数）。缺任何一问 = 在文件末尾「链路资产」节登记：链路 + 缺哪问 + 可与哪条通杀根组合（组合链不计数，仅作根的危害放大证据）。

## 状态落盘（新：接 audit-state 协议）

- 本类结论照旧写 audit-findings/<类别>.md；另在 audit-state/log.md 追加一行完成记录（含发现数）
- 若 audit-state/state.json 存在：把本类对应 coverage 格标 done/traced，新线索写入 next_round
- 涉及的发现编号 F-XXX（若主控已分配）保持一致；未分配编号时用位置 hash 临时标识
