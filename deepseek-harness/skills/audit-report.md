# 白盒审计报告（用户显式授权后）

本会话不重新审计代码，只做汇总与整合。**运行前提：用户已显式要求出报告**（说"出报告"或运行本技能即算授权）。

## 输入

`audit-state/` 目录：state.json（技术栈/覆盖度/轮次）、findings/F-XXX.md 全部档案、chains.md、pending.md、log.md。目录不存在时明确告知用户先运行审计。

**分类技能模式产物**：若工作区存在 `audit-findings/<类别>.md`（小目标/分类会话模式的结论文件，无 F-XXX 档案），一并读入——按其中「通杀判定」字段分流：通杀条目提炼进总览与详情，链路资产条目进附录A；并在报告方法节注明来源模式。

## 通杀口径（计数规则，硬性）

- **独立通杀**（findings/ 中标"通杀"的档案）单独计数——这是报告正文的唯一漏洞清单
- **组合链不计数**：chains.md 中标 `组合链=根F-XXX` 的链仅作为根的危害放大证据，在对应根的详情里引用，不进总览表
- 素材链（缺通杀条件未组合的）只在附录列出，不计数
- 报告头部明确分列：独立通杀 N 条 / 组合链 K 条（不计数）/ 待验证 M 条

## 工作步骤

1. 读 state.json + findings/ + chains.md + pending.md
2. **去重合并**：同一入口/同一链路的多条发现合并（保留最完整描述，标注"多链路"）
3. **交叉校验**（轻量）：对每条通杀 finding 抽查其引用的 文件:行号 是否真实存在——只读引用点，不重新审计；不符的降级"高度可疑"并注明
4. 按危害排序（upload-rce/deser/rce > sqli/ssrf > fileread），产出 `audit-reports/审计报告-<系统名>-<日期>.md`

## 报告结构

```
# <项目名> 白盒审计报告
## 一、审计范围与方法（技术栈、深度轮次、覆盖度 done/total、饱和度信号 X/4）
## 二、漏洞总览（仅独立通杀，按危害排序）
编号 | 类型 | 位置(file:line) | 触发请求 | 鉴权 | 危害
## 三、每洞详情（逐字来自 F-XXX.md，不新增推断）
### F-XXX [类型] 标题
前端触发点（触发请求+前端位置）/ 污点链（source→传播→sink，每环 file:line）/
净化缺口 / 关键代码（≤10 行）/ 利用条件与危害 / 组合链引用（若有：根 F-XXX 的危害放大，标注"不计数"）
## 附录A 链路资产（chains.md 素材链：缺哪问 + 可组合根；组合链：根+危害放大说明，均不计数）
## 附录B 待验证清单（pending 摘要：每条缺环原因、需要什么才能补）
## 附录C 覆盖度说明（excluded 格子及原因、未完成轮次）
```

## 硬性规则

- 不得新增任何 findings 档案中不存在的发现（可疑点写进附录，不越权下结论）
- 每条漏洞的前端触发点必须完整（触发请求+参数+方法+前端位置），缺项回原档案核对，补不齐的降级处理并注明
- 独立通杀数、组合链数、待验证数在报告中明确分列，不许含糊

最后一轮对话输出：总览表 + 每洞一句话 + 提醒哪些待验证项建议先实测再提交。
